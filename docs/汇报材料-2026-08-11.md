# Run Advisor（WeightedPaths）· 8-11 交付汇报

> 给甲方的汇报底稿：目标 → 做了什么 → 实测证据 → 数据 → 已知问题 → 下一步。
> 证据原件：docs/PLAYTEST-CHECKLIST.md（实测清单）、docs/KNOWN-ISSUES.md（已知问题真源）、scripts/eval_card_recommendations.py（评估脚本）。

## 一句话

把杀戮尖塔里的「卡」做成**有记忆、有情绪、会承诺的 AI 陪伴角色**；同时按「接入之后」的工程标准，把可靠性、可观测、可测、可验证全部闭环。

## 一、目标与定位

- 产品目标：卡从「算分工具」变成「活着的角色」——记得你、有脾气、会跟你打赌、推荐有性格。
- 技术定位：AI 是「感知 + 建议」角色（上下文 + 受控只读工具），**不直接操作游戏**；所有 AI 调用有失败分级与规则兜底。

## 二、做了什么（机制式，非许愿式）

| 维度 | 落地 |
|------|------|
| 记忆 | `run_state.json`（本局/契约/SL 恢复）+ `player_relation.json`（跨局档案）；原子写，SL 不赖账 |
| 情绪 | CardMoodEngine 状态机 + RecommendationPolicy 信任曲线（好感真的改变推荐，不是只换台词） |
| 承诺 | 契约引擎：接受/拒绝按钮、「以至少五成血量到达下一精英」、完成/违背 ±2 好感、违约记仇、完成下一份原谅 |
| 对话 | 聊天框（Tab 呼出、按钮/打字、自动换行）、卡的态度台词、道歉识别、翻页 |
| AI 可靠性 | AiResult 失败分级（NOT_CONFIGURED/TIMEOUT/HTTP_ERROR…）+ 规则兜底（无 key/AI 失败/超时永不卡游戏） |
| AI 安全 | 候选卡白名单 + 工具白名单 + 只读查询（MCP / function-calling 思路的工程化雏形） |

| 工程 | 247 测试全绿（纯逻辑 209 条无游戏 jar 永远跑）；纯逻辑/游戏层分目录；CI 打包 + artifact + tag 自动 release；版本单一事实源；KNOWN-ISSUES 真源；换机恢复指南 |

## 三、实测证据（8-11，真人进游戏）

- **契约四路径通过**：提出 → 接受（按钮）→ 完成（奖励情报实测：「后面还有 3 个精英、3 个火堆；当前路线估值领先次优约 7 分」）→ 违背（低血进精英 → 记仇）→ **SL 后契约保留**。
- 聊天输入恢复、长消息自动换行、卡奖推荐链路正常；多局零崩溃。
- 玩家真实输入被记录（`player_relation.json` 有「同意」「OK」）；探针口径修复后 per-run 计数生效。

## 四、数据（第二版评估，样本仍小）

- 测试：247 全量 / 209 纯逻辑，全绿。
- 卡奖遵循率：**57.9%**（11/19，7 局）——与首版 59.3% 一致，暂不调系数。
- AI 决策 18 条：平均延迟 **2.2s**（中位 2.3s）、工具调用 17 次、平均每 24 秒一次决策。
- **兜底率 50%**：一半决策走规则兜底——已列为 KNOWN-ISSUES K3/K14，下一步做超时/节流分析。
- 日志质量：agent_log 18/18 可解析（修复了 `need` 字段非法 JSON 与测试污染真实日志两个问题）。

## 五、已知问题（均非阻塞，已登记）
