# 决策记录（ADR）

> 记录本工程的关键设计决策：**背景 → 选项 → 决定 → 理由 → 影响**。
> 决策理由比决策本身更值钱——让「为什么这么做」不随记忆消失。

## ADR-001：用「三端口」作为卡牌评分唯一维度

- **日期**：2026-08-05
- **状态**：已采纳（核心底层逻辑）
- **影响范围**：`FourLayerScorer` / `CardScorer` / `silent_cards_a20.json`

### 背景

外部攻略用「毒贼/刀贼/弃牌流」组织内容，但这些是结果而非原因。

### 决策

DAMAGE / BLOCK / ENGINE 三端口为唯一评分维度，禁止流派标签进入评分。

### 理由

1. 流派锁死决策；端口可快照成点数（`damagePoints` 等），可程序化、可测试。
2. 遗物/单卡/路线都能映射到端口，避免流派重复冲突。
3. 抗补丁过时——「缺什么端口补什么」是稳定原则。

### 影响

- 评分可测试（本次已加 JUnit）。
- 外部攻略须端口化重述（见知识库 `猎手/端口化.md` §6）。

## ADR-002：路线评分用「硬规则」而非「软权重」处理极端情况

- **日期**：2026-08-05
- **状态**：已采纳
- **影响范围**：`WeightedPaths.refreshPathValues` / `SilentRouteValuation`

### 背景

用户反馈「血量很低仍推荐打精英，跟路线容易死」。旧实现用软权重（火堆 ×2.0），但软权重改变不了路线总分，刷新了也没用。

### 决策

对保命等极端场景用**硬规则**：血量 < 30% 且地图有火堆 → **过滤掉不含火堆的路线**，强制推荐含火堆的路（而非调权重）。涅奥白嫖精英同理（乘 2.0 且绕过端口门槛）。

### 理由

软权重是「加分」，改变不了 `getBestPath()` 的排序；硬规则是「删选项」，确定改变推荐结果。

### 影响

- 行为确定、可测试（新增 `shouldForceRestRoute` 等纯判断）。
- 需小心边界：地图无火堆时回退原列表，避免无路可走。

## ADR-003：引入 JUnit 测试基础设施 + 浅解耦

- **日期**：2026-08-05
- **状态**：已采纳
- **影响范围**：`pom.xml` / `src/test/` / `PathValuation` / `RouteSimState`

### 背景

项目原本零测试，且评分逻辑硬依赖 `AbstractDungeon.player`，无法在测试环境运行。

### 决策

1. 加 JUnit 4 依赖 + `src/test/`。
2. 浅解耦：`PathValuation.valuate` 新增接受注入 state 的重载，游戏内调用不变。
3. surefire 用 `additionalClasspathElements` 把游戏 jar 加入测试 classpath。

### 理由

支撑自动化验证；浅解耦同时让「实时重算」和「可测试」共享同一份工作。

### 影响

- 11 个测试覆盖低血保命 / 涅奥白嫖 / 一层避精英。
- 游戏类（如 `AbstractRoom`）静态初始化依赖运行时，无法在纯测试实例化——测试只覆盖纯逻辑层。

## ADR-004：玩家可见文本一律简体中文

- **日期**：2026-08-05
- **状态**：已采纳（UI 规范）
- **影响范围**：所有玩家可见文案

### 决策

玩家可见文本用简体中文；代码标识符、日志、配置 key、Mod ID 保留英文。UI 字符串用 Unicode escape 编译（UTF-8 安全，见 `ModUiStrings.java`）。

### 理由

Mod 面向中文玩家，降低理解成本。
